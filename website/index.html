Why the whole session is not a single archive

I wanted to upload the entire Session as .7z of each track. But github only accepts 25mb?!?! WHat year is this?!?! 1999??!?!?!?

Quoted from the repository README. The practical result: stems are committed one by one, and the largest committed stem is rhY Lead-5.wav at 16,237,204 bytes.

No audio plays on this page. Nothing here starts a player, opens a window or records anything: every audio address is a plain link to the file in the repository, and downloading is your choice.

Not in this repository

  • The other 12 albums. The README counts 13 published albums; this repository holds one of them. The rest keep their own repositories.
  • A licence. The repository ships no LICENSE file and this page does not name one. The README's "Open Source, remix and plunder my pirate mateys!" line is quoted as-is; choosing a licence belongs to the project owner.
  • The two unresolved track licences. Friday, Saturday and Margaritaville stay marked licensing unresolved until the owner decides.
  • A master mixdown. Only stems are committed; no finished master for any track is in this repository.

How this site is published

The site source lives in this repository. Every change on main gets a staged build and an offline check before anything is published, and production is deployed from the staged folder build/website rather than from one person's machine.

  • Preview: cd website && node dev-server.mjs (dependency-free, refuses paths outside the site folder).
  • Check: python3 website/check.py — pages, links, the 16 track names, headers and the deploy workflow, with no network access.
  • Stage: bash scripts/build-website.sh — only the public site enters build/website; no audio, no .git, no repository root.
  • Publish: .github/workflows/deploy-website.yml to Cloudflare Pages, using secrets.CF_ACCOUNT_ID and secrets.CLOUDFLARE_API_TOKEN. Without those credentials the deploy step is skipped, not failed, so a clone cannot publish or break.

rhYmusic.com being connected to Cloudflare with least-privilege credentials, the DNS zone, HTTPS enforcement at the edge and rollback ownership all belong to the domain owner. See README.md for the same list in words.
